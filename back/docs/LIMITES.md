# Limites connues

- E-mails : le site envoie des e-mails automatiques (service SMTP à configurer, voir `deploy/definir-smtp.sh` ; sans SMTP, rien n'est envoyé et le site fonctionne normalement) : bienvenue à l'inscription (développeur et recruteur), compte recruteur validé ou refusé, lien de réinitialisation du mot de passe et confirmation de changement. Un échec d'envoi n'empêche jamais l'action (il est écrit dans les journaux : `journalctl -u gamelia-api`) ; il n'y a pas de file d'attente, donc un e-mail est perdu si l'API s'arrête à cet instant, et l'admin doit alors prévenir le recruteur lui-même. Sans SMTP, « Mot de passe oublié » renvoie vers l'équipe (`npm run reset-password`). Les adresses e-mail ne sont pas vérifiées à l'inscription (aucun lien de confirmation).
- Vérification GitHub : l'API lit la bio publique du compte sur `api.github.com`, sans clé (60 lectures par heure pour tout le serveur). Au-delà, la vérification affiche « réessayez dans quelques minutes ».
- Connexion avec GitHub (OAuth) : facultative, activée seulement si `GITHUB_CLIENT_ID` et `GITHUB_CLIENT_SECRET` sont renseignés. Droits demandés : `read:user` et `user:email` (aucun accès aux dépôts) ; le jeton GitHub n'est pas conservé. Un compte GitHub n'est **jamais** relié automatiquement à un compte existant de même adresse e-mail (risque d'usurpation) : le membre doit se connecter puis cliquer « Lier mon compte GitHub » sur son profil. Seuls les comptes développeurs peuvent être créés ainsi ; un compte créé avec GitHub n'a pas de mot de passe tant que le membre n'en définit pas un (Paramètres). La connexion avec Google n'est pas proposée (elle exige un vrai nom de domaine).
- Supprimer son compte efface aussi ses questions, avec les réponses des autres membres qui s'y trouvaient (suppression en cascade).
- Next.js 14.2.35 est la dernière version de la branche 14 ; `npm audit` signale des avis corrigés seulement en version 15 ou 16. Le passage à la version 15 n'a pas été fait à trois jours du dépôt (changement majeur, et Next 15 embarque `sharp`/`libvips` sous LGPL, incompatible avec l'article 6 du règlement). Mesures prises : optimisation d'images désactivée et adresse `/_next/image` fermée par nginx (les avis critiques la concernent), aucune Server Action, aucun middleware, aucune réécriture d'URL, serveur Linux. Restent des avis de déni de service sur les composants serveur.
- Le score « semaine » du classement est la vraie somme des points sur 7 jours (le mock du front utilisait une estimation).
- Un signalement sur un contenu inexistant est refusé (404) ; le mock l'acceptait.
- Le site et l'API doivent être en HTTPS en production, derrière le même domaine (configuration du VPS) ou un même domaine parent (`COOKIE_DOMAIN`).
- Pas d'envoi de fichiers sur le serveur : la photo de profil est réduite à 256 px dans le navigateur et enregistrée en base (JPEG, PNG ou WebP, 150 Ko au plus) ; les démos sont des liens externes (vidéos limitées à YouTube et Vimeo).
- Les sessions expirées sont purgées au démarrage puis chaque heure.
- Messagerie : pas de temps réel (WebSocket) ; le front relit la conversation toutes les 10 secondes et le compteur de non-lus toutes les 30 secondes. Pas de pièces jointes.
- Agnès : dépend du service externe Agnes AI (disponibilité et quotas de la clé). Sans clé, l'espace s'affiche « indisponible » et le reste du site fonctionne. Chaque membre est limité à `AGNES_LIMIT_PER_HOUR` demandes par heure ; les discussions privées avec Agnès ne sont pas enregistrées côté serveur (elles restent dans l'onglet du navigateur). Une piste d'Agnès sur une question est générée une seule fois puis partagée ; elle n'est pas régénérée si la question est modifiée.
